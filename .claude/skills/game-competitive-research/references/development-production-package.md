# AI 就绪生产开发包标准

在完成竞品采集和模板选择后使用。竞品证据层保持不可变，目标项目生产层单独添加；竞品实现是参考证据，不是可直接克隆的规格。

## 模板选择与合并文档

1. 从 `systemGameplay.systems[]` 开始，只纳入有证据 ID 或 `templateMatch.status: confirmed` 的系统。
2. 优先准确 `templateSystemId`；否则只有规范化名称唯一命中 S01-S64 时才匹配。
3. 通过 `development-templates-v3/manifest.json` 只加载命中的 `systems/Sxx.md` 和 `shared/global.md`。
4. 竞品证据规格、策划判断和 v3 母版基线必须分为明确小节。未匹配系统继续保留并记录映射问题，不得猜测或加入全部类型推荐系统。

每个游戏版本合并为一份开发文档，至少包含：产品前提、受众、体验支柱和非目标；核心原型/玩法/循环/Meta Loop；空间、场景、主界面和验收视觉契约；通用系统架构与依赖；逐系统证据规格；适配后的 A-H 基线（状态、权威、结构、UI、资源、分析、性能、测试）；内容/成长/经济连接；条件触发的互动剧情结构；指标、证据缺口、排除系统和待映射项；实体、状态机、接口、资源、测试和任务的 AI 生成契约。

竞品内容之后增加明确标记的“目标项目补全层”，应用档位和完整性门槛。统一输出字段级模型、草案 SQL、JSON Schema、TypeScript 类型、种子数据、API、事件、UI 状态、美术生产、测试和里程碑任务。未关闭功能、数据、视觉或资源缺口前必须为 `blocked`。

用户预览和 MD/PDF 不显示知识版本、采集时间、母版文件名/哈希、用途、边界等参考文档说明；机器溯源只放 AI JSON。

## 生成档位

- `logic-prototype`（逻辑原型）：验证规则、状态和数据；核心循环必须有线框、可读反馈和空间灰盒；允许清楚标记的占位资源，非核心终稿列为后续工作。
- `visual-vertical-slice`（视觉切片）：用已通过的 Style Frame、空间灰盒和代表性终稿资源验证核心循环；必须交付核心场景、对象/角色、核心路径 UI、动画、VFX、SFX，并区分 P0 切片和后续批量资源。
- `production-ready`（生产就绪，默认）：基础、数据/API/事件、恢复、资源权属与验收完整；全部 UI、场景、角色、建筑、地块、道具、动画、VFX、音频和技术资源均为版本化、可发布终稿。

档位必须实质改变文档和每条资源的 `本档交付`。始终保留未来完整资源总表，但明确本档实际工作。页面中的游戏、档位、引擎、目标平台、网络拓扑、存档模式和美术来源均为下拉框；技术选项保留 `待确认`，不得从截图推断引擎或架构。

## 证据层与项目层

每条系统或需求标为 `competitor-confirmed`、`competitor-inferred`、`project-baseline`、`target-added`、`assumption` 或 `unresolved`。目标项目新增项绝不写回竞品快照。

## 完整性门槛

每个确认系统必须有目的、入口、输入、规则、状态、输出、依赖、UI 反馈、数据实体、分析事件、失败/恢复和验收。根据档位补齐配置/版本、账号/档案/存档、库存/货币/奖励账本、导航/生命周期、教程/解锁、设置/本地化/音频、遥测/错误、网络/幂等/恢复、LiveOps 发布和商业安全等基础。

任何必需项、模板映射、视觉契约或生产资源门槛未解决时，`implementationGate.status=blocked` 并列出阻塞项。

## 数据与接口产物

合并单系统结构为统一逻辑/物理模型，生成字段表、可执行草案 SQL、JSON Schema、TypeScript 类型、示例数据、API 契约和事件目录。配置、玩家状态、交易/资产账本、分析数据分离；复合字段、外键、索引、迁移、保留、分片和权威归属需技术审核。

## 核心玩法视觉契约

尽可能保持证据可支持的投影、镜头语法、场景/HUD 比例、世界/屏幕空间边界、视觉密度、深度/遮挡、光影和动画语言，并给出拒绝标准。相似目标只针对空间语法和体验，不得复制受保护资产。除非竞品证据如此，不得使用通用卡片/列表替代世界空间核心场景。

## 美术生产门槛与完整清单

合并以下资源：命中系统 Part B 的 UI、Part E 的美术/音频/技术资源、条件触发的互动剧情资源，以及 `visualPresentation` 中的世界空间场景族、HUD/UI、动画/VFX、Style Frame 和灰盒验收资源。清单虽为一个导出，但 UI 与资源行可筛选。

每行必须包含资源/界面名、规格和用途、`本档交付`、选择的生产来源、验收、来源模式、程序生成许可、负责人、状态、引用 ID、源格式、运行格式和许可。完整清单同时出现在 MD/PDF、AI JSON 和独立美术 List 中，且放在开发文档倒数第二部分。

美术来源必须覆盖逐行策略，同时把母版提示保留在独立溯源字段：

- `supplied-or-commissioned`：分层源文件、委托权属和交付验收。
- `ai-generated-bitmap`：每行记录模型/版本/提示词/Seed、人工重绘与分层、商用审核和运行时适配；`模型提示词` 必须针对资源用途和视觉契约，要求原创且禁止复制受保护标识/资产，并显示在所有导出中。
- `licensed`：购买凭证、许可范围、修改记录和到期/平台限制。
- `placeholder`：显眼占位标记和强制替换负责人/任务，仅逻辑原型可用。

视觉切片与生产就绪档：Style Frame 和空间灰盒未通过前阻塞最终核心场景；关键场景和界面禁止程序替代；程序化内容只有作为明确批准的视觉技术时才可用；占位仅限逻辑原型。

## 输出与实施顺序

离线 HTML 固定四项：MD、浏览器打印/PDF、AI JSON、美术资源 List；HTML 是预览，不是第五种下载格式。命令行还写入结构化目录和 ZIP。AI JSON 保留源哈希、选中系统文档、匹配方式、排除系统、适配 A-H、完整美术清单、证据缺口和适配边界。

实施顺序：架构/结构/Style Frame → 空间灰盒与代表资源 → 核心循环切片 → 支撑系统集成 → 商业化/存档/恢复 → 功能、视觉、性能和回归验收。每阶段必须有退出条件，不得让实现 AI 一次完成所有系统。
