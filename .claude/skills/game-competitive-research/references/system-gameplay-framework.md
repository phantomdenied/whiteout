# 系统与玩法框架

## 分类顺序

```text
市场类型 → 1 个主核心原型 + 1～3 个副核心原型 → 玩家动机与主要决策
→ 核心循环 → Meta Loop → 核心玩法视觉契约 → 通用系统层
→ 具体系统与依赖 → 内容/数值验证与产品指标
```

## 十五种核心原型

操作、射击、战斗构筑、阵容、卡牌、策略、经营、建造、生存、探索、解谜、叙事选择、收集、社交、创作。

## 七个通用系统层

1. 核心玩法：玩家反复执行和决策的内容。
2. 成长：永久能力或资产为何增长。
3. 内容：在哪里验证成长与熟练度。
4. 经济：产出、货币、兑换、库存和消耗。
5. 社交：关系、合作、竞争、身份和 UGC。
6. 长线运营：用新目标和奖励重复/限时包装已有玩法。
7. 商业化：价值欲望、短缺或便利、交易、奖励/内容和继续游玩。

不得强制七层全部激活；不适用时记录 `notApplicable` 与原因。

## 系统详情标准

每个主要系统记录：目的与玩家价值；入口、前置和依赖；输入、规则/状态迁移、输出、成功/失败；成长/经济连接；内容/更新节奏；UI/反馈；边界与风险；证据 ID 和未知项。

系统与 S01-S64 唯一、明确匹配时填写 `templateSystemId`。它只用于加载复用开发基线，不代表竞品采用母版的脚本、Prefab、状态名或资源规范。

## 核心玩法视觉表现

阅读 `visual-presentation.md`，分别用证据研究空间表现、场景美术、主界面构图和美术验收。这一层定义玩家如何看见和操作核心玩法，而不仅是规则。除非竞品证据本身如此，不得把世界空间核心场景替换成通用卡片/列表界面。
