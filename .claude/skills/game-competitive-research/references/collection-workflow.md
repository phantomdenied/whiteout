# 采集工作流

## 来源优先级

1. 游戏官网、商店页、更新公告、新闻和官方账号。
2. 平台自有商店、社区、榜单或活动页。
3. 开发商/发行商访谈与财务材料。
4. 成熟的专业媒体和数据库。
5. 社区内容仅用于情绪与可观察行为，不得单独证明产品事实。

总览指标按 `data-sources.md` 的路由和访问限制采集。数据商名称不等于可信等级；官方、第三方观察、模型估算、推断和授权导出必须区分。

## 证据规则

- 保存标题、URL、发布者、发布日期（若有）、访问日期、来源类型和范围；每条结论关联证据 ID。
- 分开当前事实、历史事实、观察、推断和建议。
- 未知项写入证据缺口，不得无来源推测档位、节奏、玩家数、流水或活动规则。
- 当前状态、节奏、商业化和社区运营变化频繁，必须在本次采集时联网核验。
- 总览指标应记录 `sourceProvider`、`sourceType`、平台、地区、`asOf`/`period`、范围、估算类型、置信度和证据 ID。
- 严禁保存 API Key、Cookie、账号令牌和付费数据凭据。付费来源只能使用公开材料或用户授权的导出/API 会话；不得绕过登录、付费墙、robots、反爬或限速。

## 新鲜度与版本

使用 Asia/Shanghai 日期。联网前运行 `plan-collection.mjs`：今日已有最新版则 `skip`；新游戏全量采集；旧游戏从上版 `coverage.to` 增量采集并写成完整新快照；用户明确全量刷新时才忽略同日规则。永远追加版本，不替换旧版本。

## 写入前完成门槛

- 有基本身份和至少一个官方来源。
- 上线时长由有来源的上线日计算，并带 `asOf`。
- 阶段流水、日活带时间范围并标为报告值/估算/推断；没有时写入 `basic.evidenceGaps`。
- 相关平台有商店 ID；`marketMetrics[]` 保存可用榜单、评分/评论、下载、在线、玩家数、价格、版本或授权估算。缺失项不得猜测。
- 目标人群区分有来源的人口属性与行为/动机推断，并带置信度和证据。
- 系统与玩法包含主核心原型、核心循环、系统层覆盖，以及有证据的 `visualPresentation`（空间、场景、主界面、美术验收）。图片不足时列明缺少的截图/视频角度，不得从成片推断引擎。
- 每个主要系统必须有证据 ID；匹配母版时填写准确 `templateSystemId`，类型推荐不得预先写成事实。
- 商业化和社区模块至少有已知内容或明确证据缺口。
- 所有时效指标有 `asOf` 与证据 ID，且 `validate-knowledge.mjs` 通过。
